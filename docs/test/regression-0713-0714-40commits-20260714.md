## 二、已确认缺陷

### REG-1（高·阻断回归门禁）：88a8fc1 部分提交——门禁测试进库，被测脚本没进

- **现象**：快照 `38f91c8` 上双解释器各 **17 例失败**，全部为 `test_external_real.py::test_release_gate_rejects_unsafe_iam_targets[...]`（14 例）与 `test_release_gate_does_not_inherit_openops_values[...]`（3 例）。
- **根因**：这批用例由 `88a8fc1`（07-14 02:48）提交，用 subprocess 调 `bash scripts/release_check.sh --production-env <临时env>` 断言生产门禁拒绝不安全 IAM 地址（http、`{host}` 占位、带凭据 URL、坏主机名、`\@` 混淆、URL 编码占位等）。但 `release_check.sh` 的 `--production-env` 门禁实现**从未被提交**——`git log -S 'production-env' -- scripts/release_check.sh` 在全部历史中零命中，该实现（约 +312 行，含 is_fixed_url/is_safe_proxy_cidrs 等校验）只存在于当前工作区未提交改动里。快照里的旧版脚本对该参数视而不见、照常退出 0，测试断言 `returncode != 0` 必挂。
- **旁证**：提交信息写「mock 218 绿」——那是在作者工作区（脚本已改）跑出来的；任何人检出 `38f91c8` 都得到红色套件。
- **交叉验证**：在当前工作区跑同批用例 → **26 passed**（工作区 test 增量还多 9 例），确认工作区版本自洽。
- **修复方向**：把工作区的 `scripts/release_check.sh`（+ `backend/tests/test_external_real.py` 的 22 行增量）作为一笔提交补上；今后「测试 + 被测物」必须同笔提交。

### REG-2（中·阻断 e2e 门禁）：38f91c8 InitGuard 与 e2e smoke 自相矛盾

- **现象**：e2e 六幕中「初始化向导：三步骨架」失败——`/init` 页面上 15s 等不到「选择模板」。
- **根因**：`38f91c8` 给 `/init` 加 InitGuard：`me.has_instances=true` 即重定向到工作台。mock 模式 demo 身份**恰好自带实例**（`agt_pay_fast_recovery`，e2e 第 4 幕就靠它过的），所以 e2e 一进 `/init` 就被弹走。提交信息自己写了「mock has_instances=true 访问 /init 直接跳」——**作者明知 mock 下会跳转，却没同步改 e2e**。`npm run e2e` 是 release-checklist §④ 门禁项，此后必红。
- **修复方向**：e2e 该幕改用无实例身份进向导（mock 层给 e2e 提供 has_instances=false 的开关/路由拦截），并**新增一幕断言 InitGuard 重定向行为本身**（有实例访问 /init → 落到 /agent-teams/…/chat）；两种行为都值得被锁住。

### 核查后排除（非缺陷）

- **InitGuard 空指针边界**：`recent_instance_id ?? currentAgentId` 疑似可导航到 `undefined`。核查：后端 `/me` 中 `has_instances` 与 `recent_instance_id` 同源于 `active` 列表（identity_service.py:38-39），has_instances=true 时 recent_instance_id 必非空；前端 currentAgentId 亦有非空默认值。安全。
